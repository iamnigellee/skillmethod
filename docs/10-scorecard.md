# 质量评分卡

## 技能成熟度模型

| 阶段 | 名称 | 准入标准 |
|------|------|---------|
| **L0** | 草稿 (Draft) | 有 description + body。作者在 3 个手动提示上测试。无误触发 |
| **L1** | 已验证 (Validated) | 通过 Tier 2 测试：4+ eval，精度 ≥95%，召回达标，硬断言 100%。经过一人 peer review |
| **L2** | 认证 (Blessed) | 通过 Tier 3 测试。平台团队所有。有前置条件/回退段。frontmatter 完整（版本、合规级）。季度评审已安排 |
| **L3** | 关键路径 (Critical) | 集成到 CI。回归套件在每次平台更新时运行。有指定 on-call owner。失败有 SLA |

**升级**：通过目标级别的所有准入标准。
**降级**：季度评审发现不再满足准入标准时自动降级。

---

## 通用评分卡

对每一项评为 通过/不通过。技能必须通过其成熟度级别要求的所有项。

### 描述质量（所有级别）

- [ ] Description ≤ 1024 字符
- [ ] 使用第三人称
- [ ] name 字段：小写+数字+连字符，≤ 64 字符，不含 "anthropic"/"claude"
- [ ] 包含明确的 TRIGGER 场景列表
- [ ] 包含 SKIP 列表覆盖相邻领域
- [ ] Description 与 body 语义对齐（读完 description，body 前 50 行在意料中）

### 范围设计（所有级别）

- [ ] 映射到恰好一个动词-名词对（"帮我 [动词] [名词]"）
- [ ] Body 内无 "如果用户想要 [不同动词]" 的分支
- [ ] 指令体 ≤ 400 行（有结构可到 600，硬上限）

### 指令质量（L0+）

- [ ] 每条指令是触发/检查/动作/分支之一
- [ ] 意图在流程之前陈述
- [ ] 引用活数据源而非硬编码
- [ ] 先做事后解释（不先征求许可除非破坏性操作）
- [ ] 决策树深度 ≤ 3 层

### 安全性（L1+）

- [ ] 前置条件已列出，含检查命令和回退行为
- [ ] 无跨技能依赖
- [ ] 关键约束在前 50 行和最后 30 行重复
- [ ] 脚本已审查：无 eval/exec/sudo/凭据

### 测试覆盖（L1+）

- [ ] Eval 数量达到成熟度级别最低要求
- [ ] 触发精度 ≥ 95%
- [ ] 触发召回率达到领域宽度目标（窄≥90%/中≥80%/宽≥70%）
- [ ] 硬断言通过率 100%

### 多平台（L1+）

- [ ] 核心工作流在无工具环境下可完成
- [ ] 工具增强使用能力检测（非平台命名）
- [ ] 脚本有散文版回退

### 企业治理（L2+）

- [ ] frontmatter 含 version（semver）
- [ ] frontmatter 含 owner 和 review-by
- [ ] frontmatter 含 compliance-tier
- [ ] frontmatter 含 business-case（2-3句）
- [ ] 最近一个季度内已审查

### 关键路径（L3）

- [ ] 回归套件集成到 CI
- [ ] 有指定 on-call owner
- [ ] 失败有 SLA 定义
- [ ] 变更有 changelog 记录

## 快速评估：3 分钟检查

对于快速评估任何技能，回答这三个问题：

1. **触发测试**：用一个模糊近似查询测试。它触发了吗？（不应该）
2. **爆炸半径**：这个技能能做的最危险的事是什么？用户知道吗？
3. **输出锚定**：运行两次相同查询。输出结构一致吗？

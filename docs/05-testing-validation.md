# 测试与验证

## 三级测试体系

### Tier 1：原型级（个人使用，迭代阶段）

| 维度 | 规格 |
|------|------|
| 测试数 | 3 次手动调用：1 正常路径 + 1 边界 + 1 非触发（不应激活） |
| 指标 | 二元：触发正确？输出匹配意图？ |
| 工具 | 直接 CLI 调用，无 evals.json |
| 时间 | 每迭代 5 分钟 |
| 可跳过 | 基线对比、纵向追踪、多模型测试 |
| 不可跳过 | 非触发测试。全触发的技能比不触发的更糟 |

### Tier 2：生产级（团队共享，已发布）

| 维度 | 规格 |
|------|------|
| 测试数 | evals.json 含 4-5 用例：2 正常 + 1-2 边界 + 1 对抗 |
| 触发测试 | 10 查询 via run_loop.py：5 应触发 + 5 不应触发（含 2 近似） |
| 指标 | 触发精度 >90%，硬断言 100%，基线对比至少 1 个正常路径 |
| 工具 | evals.json, run_loop.py, 双 Claude 法（A 创建 B 测试） |
| 模型 | Sonnet（主测）+ Haiku（底线） |
| 时间 | 30-60 分钟 |

### Tier 3：企业级（全组织，业务关键）

| 维度 | 规格 |
|------|------|
| 测试数 | 6-8 用例：3 正常 + 2-3 边界 + 1-2 对抗 |
| 触发测试 | 完整 20 查询：含刻意近似 |
| 指标 | 精度 >95%，召回率按域宽（窄≥90% 中≥80% 宽≥70%），硬断言 100%，基线胜率 >70% |
| 工具 | 全 Tier 2 + 盲评基线 + 三模型（Haiku/Sonnet/Opus） |
| 附加 | frontmatter 含业务案例，季度评审 |
| 时间 | 首次半天，季度评审 1-2 小时 |

## 三级断言框架

| 类型 | 性质 | 示例 | 适用 |
|------|------|------|------|
| **硬断言** | 二元通过/失败 | "生成代码可编译"、"输出是合法 JSON" | 所有技能，必须 100% |
| **软断言** | 量化阈值 | "响应 < 500 token"、"遵循格式 4/5 项" | 捕获回归 |
| **比较断言** | 优于基线 | "有技能的响应在准确性上评分更高" | 创造性/混合技能 |

## 触发测试设计

### 10 查询的推荐分布（Tier 2）

**5 个应触发查询**：
- 3 个明确触发（直接使用触发关键词）
- 1 个隐含触发（同义词或间接表达）
- 1 个多意图查询（技能相关意图是次要的）

**5 个不应触发查询**：
- 2 个明显不相关
- 2 个近似查询（话题相邻但超出范围）
- 1 个模糊查询（可能被误解释）

### 对比案例

**好的非触发测试**（针对 pdf 技能）：
```
"帮我编辑这个 Word 文档的格式"  ← 近似但不同格式
"把这段文字转换成 Markdown"      ← 涉及文档但非 PDF
"这个图片里的文字是什么"          ← 类似 OCR 但非 PDF
```

**差的非触发测试**：
```
"今天天气怎么样"                  ← 太远，无法测试边界
"帮我写个排序算法"                ← 太远
```

## 前置快速反馈（在正式 Eval 之前）

### 1. 触发优先开发
写完 description 后，立即测 3 个查询：精确匹配、同义词、不相关。不通过不继续。

### 2. 指令衍射诊断
调用后直接问 Claude："你使用了技能指令的哪些部分来生成响应？" 这揭示哪些指令被忽略。

### 3. 增量指令叠加
从 3-5 行指令开始。跑通一个正常路径。然后逐一添加约束，每次添加后测试。

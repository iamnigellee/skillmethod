# 核心原则：五大隐藏模式

这些原则不是单一角色的观点，而是 10 个角色交叉验证后涌现的深层规律。

---

## 原则一：可验证边界 (The Verifiable Perimeter)

**结论**：只有结构化约束（正则匹配、输出锚定、格式模板）才能同时满足安全性、可测试性和可维护性。内部过程指令（"仔细思考"、"要全面"）在三个维度上全部失败。

**正确做法**：
```markdown
每次响应必须以状态行开头，格式为：
`[STATUS: ok|warning|error] 十字以内摘要`
```

**错误做法**：
```markdown
请仔细检查你的推理过程，确保输出是正确的。
```

**为什么**：结构化约束可以被 QA 测试（检查输出是否匹配格式）、被安全审计（验证行为边界）、被长期维护（格式不会因模型更新而漂移）。而"仔细检查"无法被任何人验证。

---

## 原则二：注意力-信任权衡 (The Attention-Trust Tradeoff)

**结论**：LLM 对指令的注意力呈 U 型曲线——前 50 行和后 30 行权重最高，中间段（200-350行）是"低注意力区"。因此：

| 位置 | 应放置的内容 | 原因 |
|------|-------------|------|
| 前 50 行 | 关键约束 + 快速启动路径 | 最高注意力，建立行为基调 |
| 51-200 行 | 决策树和分支逻辑 | 中等注意力，适合结构化内容 |
| 200-350 行 | 参考表格、查找数据 | 低注意力区，但按需检索不受影响 |
| 最后 30 行 | 重复关键约束 + 边界情况 | 接近输出，注意力回升 |

**关键规则**：任何违反后果严重的约束，必须在前 50 行和最后 30 行各出现一次。

---

## 原则三：引用文件悖论 (The Reference File Paradox)

**结论**：外部引用文件产生二元失败模式——模型要么每次都加载（浪费 context），要么从不加载（输出错误）。

**正确做法**：把约束内联到 SKILL.md，只把可选的深度文档外部化。
```markdown
## 输出格式（内联在 SKILL.md 中）
表格列宽：名称(20%) | 类型(15%) | 描述(65%)
日期格式：YYYY-MM-DD（ISO 8601）
```

**错误做法**：
```markdown
请参考 style-guide.md 中的格式规则。
```

---

## 原则四：失败披露阈值 (The Failure Disclosure Threshold)

**结论**：技能应该在工作时隐形，在失败时诚实——且"诚实失败"必须是可验证的输出，而非模糊的免责声明。

**正确做法**：定义一个明确的失败格式：
```markdown
当无法完成任务时，输出：
`[SKILL_CANNOT_PROCEED: 具体原因]`
然后建议替代方案。绝不要默默失败或猜测答案。
```

**错误做法**：
```markdown
如果你不确定，可以适当提醒用户。
```

---

## 原则五：触发-范围耦合定律 (The Trigger-Scope Coupling Law)

**结论**：技能的触发精度和爆炸半径不是独立变量——它们是耦合的。宽触发器迫使宽指令集，导致 context 污染和维护腐烂。

**公式**：窄触发器 + 窄范围 + 窄爆炸半径 = 必须同步移动

**正确做法**：`python-type-error-detection`（窄触发，窄范围）

**错误做法**：`code-helper`（什么都触发，什么都做，什么都做不好）

# 反模式目录

## 描述层反模式

### 1. 厨房水槽描述
```yaml
# BAD
description: Handles all code tasks including reviewing, writing,
  debugging, refactoring, testing, documenting, and deploying.
```
**症状**：触发面太广，劫持不相关对话，与其他技能冲突。
**修复**：拆分为独立的动词-名词技能。

### 2. 纯否定描述
```yaml
# BAD
description: Don't use this for non-CSV files.
```
**症状**：模型无正向信号激活。技能永远不触发。
**修复**：列举正向触发场景，否定作为补充。

### 3. 路由信息放在 Body 里
```markdown
# BAD（在 body 中）
## 何时使用本技能
当用户想要处理 PDF 文件时使用本技能...
```
**症状**：Body 在触发后才加载，此信息永远不参与路由决策。
**修复**：所有 "何时使用" 信息放入 description。

## 指令层反模式

### 4. 模糊指令（Hedge Instructions）
```markdown
# BAD
你可能想考虑检查文件是否存在。
```
**症状**：Claude 将模糊语言视为可选。行为不确定。
**修复**：如果你的意思是"总是检查"，就写"总是检查"。

### 5. 矛盾指令
```markdown
# BAD
绝不未经许可修改文件。
自动修复生成代码中的 lint 错误。
```
**症状**：Claude 随机解决矛盾。行为不一致。
**修复**：用显式优先级解决："修复你自己生成的代码的 lint 错误。绝不修改已有文件。"

### 6. 人格描述
```markdown
# BAD
你是一个热情、博学的助手，热爱编程。
```
**症状**：浪费 token，零行为影响。技能是流程不是人格。
**修复**：删除。每一行应是触发条件、检查、动作或分支。

### 7. 无锚定的 always/never
```markdown
# BAD
始终编写测试。
```
**症状**：用户要求一行 shell 命令时也生成测试。
**修复**：限定范围："生成包含多个导出函数的模块时，附带测试文件。"

### 8. 过度过程化
```markdown
# BAD（模型已知的通用步骤）
验证 JSON：1. 检查以 { 或 [ 开头 2. 检查字符串引号 3. 检查括号匹配...
```
**症状**：微步骤枚举反而降低性能，强迫模型进入低效串行模式。
**修复**：命名动作和成功标准："用 json.loads() 解析并检查 schema。失败则重试。"

## 架构层反模式

### 9. 文档墓地
```
skill/
├── SKILL.md
├── README.md            ← 无人读
├── CHANGELOG.md         ← 无人读
├── INSTALLATION.md      ← 无人读
├── QUICK_REFERENCE.md   ← 与 SKILL.md 重复
```
**症状**：额外文件要么是死权重，要么让 Claude 错误加载。
**修复**：技能是给 AI 的，不是给人浏览仓库的。只保留 SKILL.md + 必要引用。

### 10. 引用深度嵌套
```markdown
# BAD
SKILL.md → references/guide.md → references/sub/detail.md → ...
```
**症状**：Claude 可能只部分读取嵌套引用。信息丢失。
**修复**：保持一级深度。所有引用直接从 SKILL.md 链接。

### 11. 自由度错配
```markdown
# BAD: 对脆弱操作给高自由度
请用你认为最好的方式填写 PDF 表单。

# BAD: 对创造性任务给低自由度
报告必须恰好包含5个段落，每段恰好3句话。
```
**修复**：确定性操作 → 脚本（低自由度）。创造性输出 → 意图+边界（高自由度）。

## 不该存在的技能

| 类型 | 为什么不该是技能 | 替代方案 |
|------|----------------|---------|
| "总结这个文档" | 基础模型已经擅长 | 直接用，除非有特定领域格式要求 |
| "写一个 Python 函数" | 通用代码生成是核心能力 | 只在涉及内部框架/API 时做技能 |
| "和我聊聊 X" | 开放对话 = 系统提示，不是技能 | 用系统提示调整对话风格 |
| "DevOps 全能助手" | 太宽，每个子能力都做不好 | 拆分为部署/监控/CI各自独立 |
| 包装单个命令 | 比函数调用还薄 | 直接告诉用户运行命令 |

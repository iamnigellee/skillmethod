# 多平台适配

## 核心裁决：指令优先 + 渐进增强

> 技能 body 必须在零工具依赖下完整运作。这是基线。
> 然后通过能力检测添加增强行为。
> 测试：将技能 body 粘贴到任何无工具的平台，如果核心任务仍能完成，通过。

## 平台能力矩阵

| 能力 | Claude Code | Claude.ai | Claude API |
|------|------------|-----------|------------|
| 持久文件系统 | 完整读写 | 无（沙箱，临时） | 无 |
| Bash 执行 | 是，无限制 | 是，沙箱容器 | 无 |
| 网络访问 | 完整 | 有限 | 无 |
| 包安装 | 是 | 是（沙箱生命周期内） | 无 |
| 子代理 | 是 | 无 | 取决于调用方 |
| MCP 服务器 | 是 | 无 | 无 |
| 跨会话状态 | 是（CLAUDE.md） | 无 | 无 |
| Git 操作 | 完整 | 无 | 无 |

## 适配模式

### 推荐：能力检测模式（Pattern C）

不命名平台，而是测试能力。最健壮，自动适配未来平台。

```markdown
## 环境适配
开始前评估可用能力：
1. 能否执行 shell 命令？
2. 能否持久读写文件系统？
3. 能否发起网络请求？
4. 能否派发子代理？

根据能力调整：
- 全部具备：使用 Section A 的自动化工作流
- 部分（bash + 文件系统，无网络/子代理）：使用 Section A 但跳过外部验证
- 最小（无工具或仅网络）：使用 Section B 的手动推理工作流，所有输出内联
```

### 备选：条件段落模式（Pattern A）

同一 SKILL.md 中用条件块区分行为。适合差异较小时。

```markdown
如果你可以执行 bash 命令，运行 `./scripts/analyze.sh` 获取结果。
否则，请用户提供以下命令的输出：`ls -la src/` 然后基于输出进行分析。
```

### 不推荐：多版本维护

维护平台特定版本会在一周内产生漂移。不要这样做。

## 常见跨平台断裂点

| # | 断裂点 | 修复方案 |
|---|--------|---------|
| 1 | 假设脚本可执行 | 始终提供"无 bash 回退"，用推理替代执行 |
| 2 | 文件写后读（中间状态存文件） | 将中间状态保持在对话 context 中 |
| 3 | 运行中安装包 | 设计逻辑使用标准库，或声明前置依赖 |
| 4 | 子代理编排 | "如果不能派发子代理，按顺序在 context 中执行" |
| 5 | MCP 工具依赖 | 检查工具可用性，提供手动指令回退 |
| 6 | 跨会话持久状态 | 将状态作为输出返回给用户 |
| 7 | 大输出写入文件 | 检测输出方式：文件 → artifact → 内联 markdown |

## 脚本可移植性规则

- 使用 POSIX sh，非必要不用 bash 特性
- 用 `command -v` 检查工具是否存在
- 临时文件使用 `/tmp`，不用绝对路径
- 输入通过参数或环境变量，非交互 stdin
- 输出结构化 JSON 到 stdout
- 脚本保持 < 50 行
- 在 SKILL.md 中保留脚本逻辑的散文版本作为无 bash 回退
